    a: RevenueCat Paywalls (the purchases-ui module) are configured remotely in the RevenueCat dashboard. That is great for changing paywalls without app updates.     a: Use the public SDK key from the RevenueCat dashboard, keep it in local.properties and expose it through BuildConfig. Don't commit it to a public repository.

**Short answer:** fetch the current Offering, map each `Package` to a plan (package identifier
as the id, `product.price.formatted` as the price), then call `purchaseWith` with the matching
package from `onPurchase`, and `restorePurchasesWith` from `onRestore`.

## Add the dependency

```kotlin
implementation("com.revenuecat.purchases:purchases:10.29.0")
```

## RevenueCat Paywalls or your own UI?

RevenueCat ships its own Compose paywall module, `purchases-ui`, which renders paywalls designed
in the RevenueCat dashboard. The two approaches solve different problems:

| | RevenueCat Paywalls | M3 Expressive Paywall + RevenueCat |
|---|---|---|
| Where the design lives | RevenueCat dashboard (remote) | Your code |
| Change without an app update | Yes | No |
| Material 3 Expressive components | Not the focus | Yes |
| Works without RevenueCat | No | Yes, with any billing source |

More detail on the [comparison page](/comparison/).
